# dsh-usage-codex

> Codex 风格的 DeepSeek Harness 用量统计面板：6 张指标卡 · 三视图热力图 · 会话用量排行 · 点击某天联动当日明细。

本项目是 [dsh-balance-plugin](https://github.com/yxxbc/dsh-balance-plugin)（MIT，作者 yxxbc）的衍生项目：
**只保留用量统计模块**，去掉了余额监控、官方充值、三方插件管理与插件自更新，并在此基础上按 Codex
个人用量页的口径做了功能增强。原始版权声明见 [LICENSE](LICENSE)。

## 功能

| 模块 | 说明 |
| --- | --- |
| **分区标签页** | 「概览 / 趋势 / 明细」三个分区，取代原先 8 个区块纵向堆叠成一条长滚动；范围切换与刷新对所有分区生效 |
| **指标卡（6 张）** | 总消耗 · 请求数 · 缓存命中率环 · 连续天数 · 单会话峰值 · 最长聊天；下方次要指标条保留 轮次/步数/工具 · 耗时 · 性能（首 token 与 tok/s） |
| **三视图热力图** | 每日（GitHub 贡献图网格）/ 每周（柱状）/ 累计（折线）三态切换，卡片头带「少 → 多」图例；三视图共用同一个**「最近 90 个自然日（含今天）」连续窗口**，窗口内缺失日期补零；**月份标签按像素与列严格对齐**（`left = 21 + 13×col`），星期栏固定 16px 宽，一/三/五 与格子的第 0/2/4 行同高 |
| **自定义悬浮提示** | 悬停任一格子显示该日 Token、请求数、轮次 / 步数 / 工具调用；提示以 `position:fixed` 跟随格子（不被浮层滚动裁剪），替代浏览器原生 title |
| **点击联动** | 点击某一天 → 概览展开「当日明细」（该日按模型的 Token 分布），可经「查看该日调用 →」跳到明细分区看该日调用；选中日期跨分区保留，再次点击或「✕ 清除」取消 |
| **趋势分区** | 按范围的消耗趋势柱状图（y 轴刻度用 万/亿）+ 模型用量（环形图与明细表，表内含**命中率**列）+ **会话用量排行**（前 10 条，按全部历史 Token） |
| **明细分区** | 调用明细表（最近 50 条，或选中某日时该日全部明细），支持按模型筛选 |

「总消耗」与「累计 Token」取的是同一个 `stats.totals.total`，全页只保留一张卡（总消耗），不再重复显示；
Codex 的三项指标（单会话峰值 / 最长聊天 / 连续天数）以卡片形式呈现。

数据来源是 DSH 的会话 API（`sessionQuery.listSessions()` / `readSession()`）回放全部会话事件，
**不依赖会话日志的文件名**，因此对带版本号的日志（如 `session.v4.jsonl.zstd`）同样有效。
插件只聚合数字，不读取对话正文。

## 安装

```sh
dsh plugin --profile <profile> add github:yigao302-lang/dsh-usage-codex
```

本地开发（改完刷新页面即生效，宿主端改动需重启 DSH）：

```sh
dsh plugin --profile <profile> add link:/绝对路径/dsh-usage-codex
```

安装后重启 DeepSeek Harness，入口在**输入框工具行右侧的柱状图图标**。

> **生效方式**：本插件的改动都在客户端（`lib/client.js`），**刷新页面即生效，无需重启 DeepSeek Harness**；
> 若界面仍是旧版（例如指标卡只有 4 张、月份标签贴不到列上），说明拿到的还是旧脚本，强制刷新一次即可
> （macOS `⌘⇧R`，Windows / Linux `Ctrl+Shift+R`）。

## 数据口径

- Token 总量 = 输入（含缓存读）+ 输出；输出已含思考 token，不重复累加。
- 连续天数按**日历相邻**判定（非毫秒差），跨夏令时安全；今天没有用量时从昨天起算。
- 单会话峰值 / 最长聊天时长按会话聚合，取会话首末事件时间之差。
- 热力图与连续天数基于**全量历史**聚合（宿主保留最近 90 天），不受范围切换影响；
  消耗瓦片、按模型分布与调用明细仍按所选范围返回。
- 热力图三视图（每日 / 每周 / 累计）共用同一个**「最近 90 个自然日（含今天）」的连续窗口**：
  客户端按本地日历逐日构造，窗口内没有用量的日期**补零渲染**（每日视图 `level 0` 空单元格、
  每周视图 0 值柱、累计视图按 0 累加）。因此**柱数 = 列数 = 周数**（90 天 ≈ 13–14 列），
  每日视图行序固定周一 → 周日并与真实星期对齐，今天恒定落在窗口最后一格；
  分档着色以**窗口内有数据日期的最大值**为基准，窗口外（更早）的历史不参与分档、也不计入累计与卡片摘要。
- 窗口边界说明：客户端窗口按**自然日**计算（今天 − 89 天 … 今天），宿主保留期按 **90 × 24 小时滚动**截断，
  所以在保留期边界上可能有一天仍被宿主保留、却落在客户端窗口之外——该日不计入热力图卡片摘要与累计曲线。
  这是窗口口径的已知行为，不是缺陷。
- 数值格式为**中文数量级**：Token 与用量 `1e4 ≤ n < 1e8` → `X.X 万`（去尾零）、`n ≥ 1e8` → `X.XX 亿`；
  坐标轴刻度取整（`500万` / `1.5亿`）；请求数、调用次数用千分位 `toLocaleString()`。**不再使用 K/M/B**。
- 热力图对齐口径：几何值单一来源（`HEAT = {cell:10, gap:3, gutter:16, bodyGap:5}`），
  月份标签左边缘 = `16 + 5 + 13×col`（首列 `21px`，13 列末列 `177px`，14 列末列 `190px`），
  CSS 变量 `--duc-heat-cell/-gap/-gutter/-bodygap` 与之一一对应；月份标签只在「该列第一格所在月份变化」处出现。

## 开发

```sh
npm run check      # 语法检查（node --check）
npm test           # 回归测试，共 65 项断言（宿主 14 + 客户端 51）
npm run check:real # 可选：用本机真实会话日志跑一遍聚合（只读 $DSH_HOME/sessions）
```

- `lib/index.js` — 宿主端：会话事件回放、按天 / 按模型 / 按会话聚合、`/dsh-usage-codex/api/*` 路由。
- `lib/client.js` — 浏览器端：React.createElement 手写组件，无构建步骤；改完刷新页面即生效。
- `docs/design-spec.md` — 用量页重做的设计规格：信息架构（§7）、视觉规范（§9，令牌 / 字号层级 / 间距圆角 / 热力 5 档 / 万·亿格式）、热力图月份标签错位的根因与修法（§6.2）、功能取舍（§10）。

测试构成：

| 文件 | 覆盖 |
| --- | --- |
| `test/host-smoke.mjs` | 用合成会话事件驱动真实宿主代码，断言 `dailyAll` / `sessionPeak` / `longestChat` / `streaks` / `dailyModels` 字段与取值；并从 `lib/client.js` 源码提取客户端实际读取的字段，反向断言宿主全部提供（防字段漂移） |
| `test/client-render.mjs` | 最小 React 桩 + `node:vm` 沙箱加载真实 client bundle，渲染组件树并模拟「点开入口 → 点击某天 → 悬浮 → 切换三视图 → 切分区」交互；窗口语义断言：逐格悬浮回读 90 个日期核对连续无跳格、行序与真实星期对齐、缺失日补 `level 0`、每周柱数 = 每日列数且逐周聚合正确（含空周 0 值柱）、累计 90 个点且末值等于窗口内总量、时钟漂移锚定；改版断言：**月份标签像素不变式**（`16 + 5 + 13×col`）、星期栏 7 行与 一/三/五 行序、6 张 KPI 卡与「累计 Token」去重、热力图图例、会话用量排行（前 10 / 未命名会话 / `—` / 无主·子代理标签）、模型表命中率列、中文数量级格式，并把注入的样式表按 §9 逐条 grep（令牌 / 字号层级 / 间距圆角 / 热力 5 档） |

两者都不需要启动 DSH，可在 CI 中直接运行。`npm run check:real` 是另一层保险：它用**真实会话日志**（含带版本号的 `session.vN.jsonl.zstd`）驱动同一套聚合代码，用来发现合成数据覆盖不到的事件形状差异。它只读不写、不联网，输出为聚合数字。
